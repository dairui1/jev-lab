Jev + Browser：两种接法的源码对比

browser-use 的 jev-ultrafast 和 cline 的 jev-browser 插件同一天（2026-09-18）落地，共享同一套设计哲学——Jev 只做“选择”，不做“生成”；但一个是追求极限速度的独立 Python 库，另一个是嵌进 Cline 的 TypeScript 工具插件。下面是把两边代码全部读完后的结构化对比。

共同的设计基因 shared DNA

两边 README/AGENTS 里的措辞几乎逐句对应（“DONE 不是成功的证据”、“浏览器 mutation 永不重试”、“文本助手必须返回恰好一个 text 键”……），核心不变量完全一致：

Jev 只能选，不能写模型输出只能是“已观测到的元素 ID / 预定义操作”，永远不会变成 selector、坐标、JS 或 shell。
TYPE_TEXT 才叫小 LLM文本值由独立小模型从 goal + 字段 + 页面上下文推断，返回 JSON {"text": ...}，≤2000 字符，非法就不打字。
DOM 快照 ≠ 截图Jev 消费结构化状态：URL/标题/可见文本 ≤6000 字符 + 带索引的可交互元素表，排除 password/file/hidden。
先记录再观察动作执行后先写 history，再观察结果页；导航打断也不会丢掉“已执行”这一事实。
Stale 重观测，不重试动作决策时页面变了 → 丢弃决策重观测（预算 2×maxSteps）；已发出的点击/输入绝不重放。
三步无进展即 blocked连续 3 个非 WAIT 动作页面指纹不变 → 判定卡死。文本助手结果只在上下文完全相同的 stale 重试中复用。

决策回路：一次请求里问什么

这是两者最本质的架构分歧。Ultrafast 用 TypeSafe 的 speculative fan-out：一个“操作”问题 + 每种操作各自的“目标”问题，执行器只消费被选中操作对应的那个 head。Cline 插件则把 (操作, 目标) 展平成一个 choice 问题。

ultrafast 多 head 推测式 fan-out

operation 问题的 criteria 只有 5–8 项（CLICK/TYPE_TEXT/SELECT/SCROLL_*/WAIT/DONE/BLOCKED）；每个 target head 的 criteria 只含兼容该操作的元素。两个决策，一次网络往返。

cline 单 head 展平 choice

一个可点又可输入的 input 会变成两条 criteria（CLICK:3 与 TYPE_TEXT:3）。实现更简单，也天然支持 minProbability 门槛；代价是选项数膨胀，概率被稀释。

关键结论

同一个想法，两种产品形态

核心洞见相同：把浏览器 agent 从“LLM 生成动作”改成“Jev 在有限动作空间上做分类”，只在需要文本时才调 LLM。Ultrafast 是这个想法的极限压榨版；Cline 插件是它的可交付版——被更大的 agent 编排、沙箱化、带安全逃生口。

速度差主要来自三处

① fan-out 让 Jev 一次回答两个问题、且 criteria 更小；② 动作后等待是 rAF/option 事件驱动（≤200 ms）而非固定 350–600 ms；③ CDP 直连复用已有 Chrome，省掉 Playwright 冷启动和每步的 evaluateHandle 往返。

Cline 版多给 Jev 的信息值得借鉴

offscreenControls 让模型知道“要找的选项在下面，滚动而不是打开帮助”；selectedOptions 保住屏外已勾选状态。这两项直接解决长配置页上的常见误判，ultrafast 目前没有。

REVIEW 是 agent-in-the-loop 的正确形状

Jev 不能自己决定下单，但可以识别“下一步是消费性动作”并把控制权交回 Cline。这比 ultrafast 单纯的 DONE/BLOCKED 更适合真实工作流——尽管 README 也承认这是 prompt 层面的引导而非硬边界。

如果你要复现 / 集成：做研究或压延迟，读 jev-ultrafast/jev_ultrafast/ 四个文件就够了（810 行含 JS）；它的 snapshot.js 名字算法和 guard 设计比 Cline 版精细。做产品接入，Cline 插件的 jev-run.ts 状态机（7 种终止状态 + trace + 100 s deadline）和 runtime.ts 的隔离浏览器配置更值得照抄。

两边都承认的限制：不处理 shadow DOM、iframe、canvas、文件上传、嵌套滚动、弹出新 tab；accessible name 只是常见 HTML/ARIA 子集；DONE 永远需要独立验证（ultrafast 用 examples/flights.py:verify() 检查 URL 里的 tfs 参数与字段值，Cline 靠主 agent 看最终截图）。
